# PC28 过关收益模拟

## 范围

后台和公开页收益模拟支持单玩法过关：大小、单双、组合、号码、双组、杀组均可自由选择均注、倍投或过关，以及跟随预测、固定方向、只跟某方向。旧七三分注 A/B/C/D 和跟随组合结构继续保留。按所选方案已结算期号回放，不生成预测、不派单、不更改实际资金；不依赖另一个项目的部署路径。

## 计算契约

- 以 pc28touzhu 的 win_streak_roll / split_integer_stakes 为金额与关数参考：整数总注向下取整，主注向下取整，余数给辅助注；至少两注各 1U。每笔中奖净收益先舍入到分，再加回本金。
- chain 下一期风险注额等于本期返还；账户余额累计净盈亏、跨日结转。all_in 使用可用余额，未下注尾差保留，每日重新开始。
- 整期净利正/负/零分别加一关/清零/保持。达标或可下注资金不足时结束一轮。可当天收工或在后续有效期重开，受每日轮数上限限制。
- 重新投入、补足本金和每日重置提取金额独立记账，不计作收益。累计收益始终等于各期净盈亏之和。
- 日界线可选北京时间自然日（默认，与投注端默认一致）或 PC28 盘日。区间为当前日、近 7 日、近 30 日，包含当前未结束日。
- 缺开奖、缺组合、无可靠预测时间、开奖后生成的预测跳过并计数。现有表仅保留每期当前预测版本；结果标明这一限制，不宣称重建完整历史信号版本。
- 单玩法过关的组下注等额拆成整数：起始 100U 杀组三组各 33U、共 99U，余额尾差保留。整组盈利才加一关，预测覆盖命中独立展示。
- 不模拟自动触发条件。固定方向也只回放该方案有合格预测的期号；多种玩法分别计算，不混合资金。

## API 设计

沿用 `/api/predictors/<id>/simulation` 和 `/api/public/predictors/<id>/simulation`，GET 请求增加 `bet_mode=win_streak_roll`。

独立参数：`roll_structure=follow_signal|A|B|C|D`、`roll_mode=chain|all_in`、`roll_base_amount=100`、`roll_main_share=0.7`、`roll_target_streak=3`、`roll_on_target=close_day|new_cycle`、`roll_on_bust=close_day|new_cycle`、`roll_max_cycles_per_day=1`、`roll_day_boundary=natural|pc28`、`roll_days=1|7|30`。

通用玩法新增 `roll_structure=single_play`、`roll_play_type=big_small|odd_even|combo|number|double_group|kill_group`、`roll_selection_mode=follow|fixed|filter`、`roll_fixed_value`。`main_share` 只用于旧七三结构。旧请求不传 `structure` 时仍保留原默认行为。

均注／倍投共用 `metric`、`play_selection_mode=follow|fixed|filter`、`play_fixed_value`。大小方向为大/小、单双为单/双、号码为 0–27；双组为两个组合以 `+` 连接，杀组为被排除的组合。未支持某玩法预测的方案仍可模拟固定方向，但不能伪装成跟随预测。

只支持 PC28；默认 follow_signal 要求方案有 combo 预测能力。非法参数返回 400，禁止静默退回均注。已有下注策略模板与过关参数同时传入返回 400。均注、倍投及竞彩足球行为保持兼容。

响应沿用 metric/bet_mode/period/summary/records，增加 roll_config、回放口径说明、轮次统计和资金摘要；逐期明细包含两笔 legs、余额前后值、风险注额、关数、轮号和停止原因。公开汇总权限不返回逐期或逐轮内容。

## 页面

模式菜单增加“过关”；PC28 选择过关时显示有明确标签的独立配置区域，隐藏均注/倍投字段、原玩法和区间选择。后台和公开页共用过关控件及摘要生成逻辑。保留现有桌面表格和手机卡片，补充两笔注额、返还、余额及关数。修改参数后重新计算；加载、错误、空数据和汇总权限均有明确反馈。

## 使用方法

后台选择 PC28 方案，或打开该方案公开页，先选玩法和方向，再在模式菜单选择均注／倍投／过关。新页面过关默认“当前所选玩法过关”，起始 100U、链条滚动、连赢 3 关收工、每天最多 1 轮，按北京时间自然日回放。关数可自行改为 5、10 等；旧七三结构可在过关设置的投注结构中选择。

切换“下一有效期开新轮”时，需要同时把每天最多轮数提高到 2 或以上。重开只在后续有合格预测时投入资金；区间末尾不会产生空轮或虚构补资。补资在“累计投入本金”中展示，全仓重置保留的余额列入“重置时提取”。校验关系为：期末账户余额＋重置时提取－累计投入本金＝净收益。

参数只用于本次页面模拟，没有写入已保存的下注策略。公开层级为“仅统计”的页面只显示收益汇总。新模式由后端 `simulation_bet_modes` 声明能力；旧后端或缺少新组件的缓存页面继续使用原有模式。

## 验证结果（2026-11-09 UTC）

使用临时数据库验证 API 所有权、公开层级、参数边界和零写入；纯函数验证三连盈利、整期亏损、退款、金额尾差、金额分档赔率、跨日和重开资金。与投注端使用相同开奖及信号进行逐期对照。浏览器验证后台/公开页切换、参数计算、移动端与旧模式回归。

- 全量 Python 测试：313 项通过；其中新增过关测试 28 项。
- 跨项目对照：64,576 个场景，逐笔注额、返还、整期盈亏、账户余额和关数全部一致；包含 1,000 种三球开奖、四种结构、两种滚动方式、全部赔率档，以及整数尾差和金额降赔场景。
- 新回放引擎覆盖率：语句 159/177（89.8%）、分支 63/74（85.1%），综合 88%。
- Chromium：后台与公开页参数切换、旧均注/倍投、缺少组合的方案、竞彩足球隔离、慢请求覆盖保护、公开汇总权限、390px 手机布局通过。
- 生产历史库以 SQLite `mode=ro`、`query_only=ON` 进行一次抽样试算：1/7/30 日分别耗时约 284/401/626ms；三段回放资金守恒。此抽样不代表生产负载测试。

## 生效方式

本次没有新增数据库迁移或运行依赖。按现有运维方式重启 AITradingSimulator 进程后加载新后端，并刷新页面加载组件。投注端无需重启。回滚时同步回退来源项目的 Python、模板和静态文件即可；模拟没有修改任何账户或投注数据。

通用过关升级涉及两个项目：来源项目及投注端的执行相关进程都需要重启加载新代码。原有过关模拟发布记录保留在上文；本次六种玩法另增加 96,384 个跨项目场景对照，全部一致。真实资金的在途轮次应继续由支持 `single_play` 的版本完成。
