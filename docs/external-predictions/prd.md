# 外部预测方案产品需求文档

## 文档信息

- 功能名称：公共外部预测源与多用户方案
- 版本：1.0
- 日期：2026-09-18
- 状态：依据用户已接受方案进入设计与实施；不重复请求需求确认
- 适用项目：`AITradingSimulator`、`pc28touzhu`
- 本阶段授权：先检查两项目未上传代码，再设计开发；不包含自动推送 GitHub、启动运行服务和真实投注。

## 1. 背景与目标

用户希望利用免费预测 API 增加方案选择、降低重复预测成本，并为以后发现的不同网页或 API 留下扩展能力。用户已接受“管理员管理来源、用户选择方案、服务端共享采集”的方案，并授权在两项目无遗留代码时开始设计实施。

父任务已确认两项目没有未提交或未推送的既有代码、没有 stash：`AITradingSimulator main = origin/main 166364b`，`pc28touzhu main = origin/main f67f05c`。`AITradingSimulator` 原有未跟踪 `.spec-workflow` 模板不属于本次变更，不改动。

现有程序支持 AI 和机器算法两种预测引擎，方案绑定用户，并有大小、单双、组合等预测目标、开奖结算、历史和收益展示。`pc28touzhu` 已支持 `ai_trading_simulator_export`，按 `signal_id` 等标识去重，并将空 `items` 视为正常无信号。接入应复用这些能力，避免建立第二套用户方案或执行规则。

成功标准：

- 同来源同采集周期只进行一次有效请求；多名用户订阅相同或不同模型不会成倍增加上游请求。
- 管理员可配置来源和开放模型，普通用户可创建、编辑、停用自己的外部方案。
- 上游旧期、错期、缺失、改写和非法字段均有明确处理，不能产生已过期的可执行信号。
- 本地实时跟踪命中率仅由开奖前留档的预测及本地开奖结果计算。
- `pc28touzhu` 可通过现有协议完成采集、标准化、去重及模拟核对，原 AI/机器算法导出仍通过兼容验证。

## 2. 用户与流程

| 角色 | 需求 | 核心流程 |
|---|---|---|
| 管理员 | 控制公共来源、模型开放及请求成本 | 查看来源 → 测试/刷新目录 → 开放模型 → 启用采集 → 查看最近成功和失败 |
| 登录用户 | 无需自行配置 API Key 使用外部模型 | 新建方案 → 外部预测 → 来源和模型 → 玩法 → 保存 → 查看预测历史与统计 |
| 下游模拟使用者 | 复用既有用户执行设置核对信号 | 现有导出 URL → 下游来源采集 → 标准化及去重 → 模拟执行与结果核对 |

公共预测原始采集数据可以共享，用户方案名称、启停状态、目标玩法及已有分享设置仍各自独立。普通用户无权修改采集地址、连接配置和其他用户方案。

## 3. 功能需求

### FR-001：接入插件与公共来源管理（P0）

系统应区分“接入插件、来源连接、外部模型、用户方案”。JND 使用一个接入插件和一个公共来源连接管理其模型目录；模型数量动态读取，不硬编码为 100。

管理员应能够查看来源、测试连接、刷新目录、启停采集、设置有界采集间隔并开放/关闭模型。来源页面应展示连接状态、最近尝试/成功时间、最近错误、模型数量和最近有效期号。新来源默认不自动启动采集。

验收：

- [ ] 普通用户对来源配置和刷新管理接口的写操作被拒绝。
- [ ] 关闭来源或模型后，不再给依赖它的用户方案生成新预测；已有历史和来源标识保留。
- [ ] 一个来源刷新可发现全部模型；模型的稳定标识与展示名称分别保存，未知或下架模型不得静默切换到其他模型。
- [ ] 插件提供统一的目录读取、预测解析和标准化约定。后续 JSON 来源可增加插件或经管理员管理的映射配置，用户方案和下游协议无需重写。
- [ ] 本期至少交付可运行的 JND 插件；通用 JSON 字段映射的结构和扩展点有文档，不引入任意脚本执行。

### FR-002：JND 共享采集（P0）

实时采集应使用 `/api/ai-predict` 的整批模型结果。`/api/ai-prediction-history?model=quantum` 只可作为将来的历史查看/核对来源，不能替代实时获取时间证明。本期无需导入历史。

后端按来源调度，保存共享批次并分发给依赖的启用方案；用户刷新前台页面不触发外部 HTTP 请求。新一期未发布时可在有界频率内重试，成功后同一来源/期号不重复创建等价快照。接口异常必须与 AI 推理错误区分。

验收：

- [ ] 同一采集周期中，两个不同用户、多个模型共用一次 JND HTTP 请求；同时触发人工刷新和自动周期时有防重机制。
- [ ] 配置请求超时、响应体上限、最短请求间隔和失败退避；不超过对方公开限制，不能无限重试。
- [ ] 整批 JSON 校验后，单模型异常只影响对应模型，其余有效模型可使用。
- [ ] 上游不可用时显示明确原因；不调用 AI 猜测或使用上一期结果填补。
- [ ] 外部采集不为每个用户重复同步开奖或占用 AI 模型调用；来源慢请求不持续阻塞其他来源和既有预测任务。

### FR-003：多用户外部预测方案（P0）

创建/编辑方案新增“外部预测”引擎，选择管理员开放的来源、模型和玩法。仅适用于 `pc28`；玩法限定 `big_small`、`odd_even`、`combo`，分别表达大/小、单/双、大单/大双/小单/小双。主玩法和默认收益玩法必须属于所选目标。

外部方案不要求 API Key、模型调用地址和提示词。方案列表、详情及历史应显示“外部预测”、来源名、模型名和更新状态；与用户现有方案使用同一套所有权和分享设置。

验收：

- [ ] 用户可新建、编辑、启停和删除自己的外部方案；不能访问或更改他人的私有方案配置。
- [ ] 缺失来源/模型、来源停用、模型未开放、模型不支持所选目标时返回具体错误。
- [ ] 同一模型下两个用户可选择不同目标，仅各自选择的目标参与其预测展示、统计和导出。
- [ ] 修改绑定只影响后续预测，历史记录保留当时来源、模型、目标及版本。
- [ ] 界面保留既有 AI/机器算法选项与交互，外部方案不显示无意义的提示词优化或 AI 连通性操作。

### FR-004：期号、时间及不可变留档（P0）

每条外部预测应具备来源、模型、彩种、目标期号、上游发布时间（若提供）、本地首次获取时间、批次/版本标识和原始证据。有效预测必须对应本地认可的下一期，获取时尚未开奖、尚未超过截止时间；本地开奖或时间上下文无法确认时应跳过执行。

系统应明确区分“当前有效、等待更新、过期、期号不匹配、字段无效、来源异常”等结果，避免把正常等待当作需要用户反复处理的异常。

验收：

- [ ] 已开奖期号、非目标下一期和超过截止时间的预测不进入当期用户执行记录；原始记录可用于排查。
- [ ] 时间统一使用有时区的表示；时区转换和上游无发布时间的处理不以伪造时间代替。
- [ ] 同来源、模型、期号、内容重复取得时保留原首次获取时间，不制造新的实时样本。
- [ ] 上游修改同一期预测时保留内容版本；用户已采用/导出的预测不可被后续版本静默覆盖。本期默认采用首个有效版本，后续版本用于审计。
- [ ] 首次获取发生在开奖后的记录，即使上游标注较早发布时间，也不得列入本地实时跟踪统计。
- [ ] 不从组合、杀组合、号码集合或分球预测猜测另一种玩法；缺失目标字段时明确跳过对应目标或方案。

### FR-005：本地结算与统计（P0）

外部方案复用本地 PC28 开奖来源、命中规则和收益模拟规则。外部提供的命中率与 `confidence` 是来源信息，不能直接写成本地已验证表现。

验收：

- [ ] 大小、单双、组合预测在开奖后按现有规则结算，重复结算幂等。
- [ ] 仅实际采用且满足实时资格的记录计入该用户方案本地样本；等待、无效和未支持目标不伪装成命中或未命中。
- [ ] 页面可区分本地样本数量/命中表现和上游评分；未提供评分时为空，不能补造百分比。
- [ ] 历史列表能定位来源、模型、首次取得时间及采用版本，普通公开展示不暴露内部连接配置和原始批次。

### FR-006：标准导出与公开兼容（P0）

复用 `/api/export/predictors/<id>/signals?view=execution|analysis` 及 schema `1.0` 的 `items`、`signal_id`、`issue_no`、`published_at`、`signals` 等字段。来源、模型、快照引用与有效时间作为可选元数据增加；不能要求旧客户端升级后才能消费旧方案。

当前导出 URL 已被下游直接消费，应保留明确公开且分享记录的旧 AI/机器算法方案匿名执行导出。既有实现缺少权限过滤不能视为产品授权：私有方案或仅分享统计（`stats_only`）方案，仅所有者/管理员会话或按方案授权的导出 token 可读取预测。匿名访问仅覆盖显式公开的 `records` / `analysis` 范围，`analysis` 不得向匿名访问者暴露原始响应、提示词、凭据或内部连接信息。界面应清楚显示导出的公开范围，并提供私有下游连接所需的方案授权方式。

验收：

- [ ] 明确公开且分享记录的原 AI/机器算法匿名 execution 导出保持可用，URL、schema 和必要字段不变；匿名不能读取私有、`stats_only` 或未授权分析内容。
- [ ] 所有者/管理员会话及按方案授权 token 可以读取私有方案；token 不可跨方案使用，可轮换或撤销，错误响应不泄露方案内容。下游可通过其现有自定义 HTTP 请求头传递授权。
- [ ] 匿名 `analysis` 的可见字段服从分享等级，绝不包含 `raw_response`、`prompt_snapshot` 或来源连接秘密；分析展示不能绕过执行导出的权限。
- [ ] 新外部方案 `execution` 只返回当前有效、目标匹配的已采用预测；来源或方案关闭、过期、已开奖或未取得有效预测时返回 `items: []`。
- [ ] 新外部方案已结算历史可在授权的历史页面或 `analysis` 中查看，但不能混入当期 `execution`。旧 AI/机器算法的时效过滤变更需单列兼容评审与测试，不因保持旧行为而声称其全部符合新增时效保证。
- [ ] 同一方案、期号已采用版本的 `signal_id`、`published_at` 稳定，轮询不会因统计更新制造重复信号。
- [ ] 导出只包含用户选择的目标，不包含数据源凭据、管理设置或整批其他模型原始内容。

### FR-007：`pc28touzhu` 模拟闭环（P0）

下游使用已有 `ai_trading_simulator_export` 来源、标准化和用户执行规则消费新外部方案。投注金额、倍数、止盈止损继续由下游用户规则管理；上游 `message_text` 里的既有占位金额不能替代用户规则。

验收：

- [ ] 以离线固定样本证明新外部方案导出可被现有来源采集和标准化为大小、单双、组合信号。
- [ ] 相同信号重复获取复用已有记录；空 `items` 保持正常跳过，不创建空 raw item、不重放旧信号。
- [ ] 对携带有效期的外部信号，下游处理时若已过期或目标期已开奖，不建立可执行任务；缺少新字段的旧协议按既有兼容行为处理。
- [ ] 验证用户间规则和执行目标隔离，以及相同用户/期号/玩法/执行目标的幂等行为。
- [ ] 验证全过程使用临时数据库、固定时间及模拟执行器，不调用真实投注或 Telegram 发送、不修改生产订阅。

## 4. 非功能需求

- **资源**：采集量主要随来源及采集周期增长；原始响应按批次保存或设明确保留策略，用户记录只引用所需预测，避免 100 模型整批数据按用户反复复制。
- **可靠性**：进程重启后仍可识别已采用预测、首次获取时间和重复批次；迁移幂等，已有数据库记录可继续读取。
- **权限**：新增管理操作沿用管理员检查；用户配置沿用所有权检查；公共来源共享不代表用户私人配置共享。
- **网络边界**：本期来源由管理员受控配置，优先 HTTPS；没有普通用户提交任意内网地址、任意请求头或代码的入口。错误日志避免泄露凭据。
- **可观测性**：可查看来源最近状态、错误原因、目标期号和采集时间；故障信息不混用 AI 模型鉴权错误。
- **可测试性**：网络、时间和开奖上下文可注入；关键校验、并发防重及两项目契约可离线验证。

## 6. 风险与依赖

| 风险或依赖 | 影响 | 处理 |
|---|---|---|
| JND 接口免费政策、模型字段或发布时间变化 | 采集失败或时间判断不充分 | 插件隔离、有界请求、严格字段校验及失败状态；当前可访问不等于长期保证 |
| 第三方历史可能回填或改写 | 误判实时表现 | 本地首次获取证据及版本留档，历史不回灌实时统计 |
| 本地开奖结果延迟或不同来源期号不一致 | 错误执行目标 | 本地下一期及截止时间联合验证，不可确认时无执行信号 |
| 模型高度相关 | 共识样本数被误读 | 保存来源元数据，后续共识权重单独设计；本期不宣称模型独立 |
| 现有导出缺少权限过滤且下游有依赖 | 私有方案泄露，权限修复也可能改变既有连接 | 保留显式公开方案匿名消费与 schema；私有来源迁移到会话/方案 token；匿名分析移除 raw/prompt，并提供升级说明 |
| 既有服务使用全局串行锁 | 外部超时延迟其他任务 | 共享采集与网络调用有界，实施设计需避免逐用户网络等待 |

## 7. 交付与验收顺序

1. 固化数据结构、插件及协议边界，结合真实只读样本确认 JND 字段。
2. 实施数据库迁移、共享采集、有效期与不可变快照、管理 API。
3. 接入用户方案与界面、本地结算及有效信号导出。
4. 运行关键单元测试、既有功能回归及 `pc28touzhu` 离线契约/模拟验证。
5. 交付代码改动、验证结果和启用说明；不自动运行服务、推送或启动真实执行。

无阻塞需求问题。字段映射、调度间隔默认值和保留期限由架构设计结合现有运行周期确定，并在实现文档记录，不向用户重复索取已给出的产品选择。
